# 3分钟演示与技术准备

## 演示顺序

1. 20秒：说明用途——把研究规范与知识文档变成可检索、可溯源的知识库。
2. 40秒：点击Macro-F1示例，展示实际检索、右侧来源与完整原文。
3. 40秒：上传自编TXT（例如“实验服务器预约需要提前两天申请”），提问并查看自己的文档被命中。
4. 30秒：切换BM25和融合检索，说明两路是词法检索，不冒充语义检索。
5. 30秒：展示评测文件和测试，解释小合成集合的局限。
6. 20秒：说明下一步改进：加入Embedding召回、独立测试集和重排序。

## 需要自己真正理解的问题

- 为什么分块要重叠？420和80只是默认参数，如何通过评测选择？
- BM25与TF-IDF各自如何对词频和文档长度建模？
- 为什么RRF用排名而不是直接把不同尺度的分数相加？
- 为什么双路词法融合不一定提升效果？本次小评测没有显示提升，应如实说明。
- 文档级Recall与片段级Recall有什么区别？多块同源文档为何需要去重？
- 为什么引用编号正确还不能保证模型没有幻觉？如何增加忠实性评估？
- SQLite会话隔离如何实现？Cookie丢失、数据过期或服务重启会怎样？
- 为什么索引每次重建？大规模场景如何改为增量索引？
- 模型API超时如何处理？密钥为什么不能出现在前端？
- 为什么这还不是Agent？没有规划、工具循环、任务执行与反馈状态。

## 学习顺序

先读retrieval.py，再读store.py，然后main.py，最后前端app.js。每读完一个模块，自己修改一项功能并补充测试。建议先增加一个真实需求，例如文档筛选或可配置分块，并记录改动前后的评测。
